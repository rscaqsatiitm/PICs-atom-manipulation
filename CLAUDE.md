# CLAUDE.md

Rules this repository follows. The sources are `README.md` (Conventions, Running), `docs/parameters.md`,
`picsim/provenance.py` and `report/check_numbers.py`, plus the verification rules adopted in
`docs/verification.md`. Do not add rules here that are not in those places.

## Results and provenance

- Lengths are in micrometres unless stated.
- Every simulation script writes `results/<name>.json` through `picsim.provenance.save_result`: inputs with their
  provenance, outputs tagged SIM, the git revision and notes.
- Every physical input carries one provenance kind (`picsim/provenance.py`):
  - USER: proposal text;
  - SOURCE: retrieved and read in a working session, with a pointer (DOI, arXiv, link and location);
  - DERIVED: calculated, with the formula stated;
  - SIM: produced by a simulation in this repository, with the script named;
  - CHOICE: a design or sweep choice, not a claim about the world;
  - RECALLED: from memory, not verified; must be checked before use.
- `docs/parameters.md` is generated by `scripts/m7_budget.py` from the inputs of `results/*.json`. Regenerate it;
  never edit it by hand.
- Simulated values are valid only inside the simulated regime and must be reviewed before they are quoted in the
  proposal.

## Report numbers

- Every number in `report/sections/*.tex` must occur in `docs/*.md`, `README.md` or `results/*.json`.
- `make check-numbers` runs `report/check_numbers.py` and fails on any unmatched number.
- An unmatched number that is genuinely not a result goes in `report/number_allowlist.json` with a reason. An entry
  without a reason fails the check.

## Commands

- `make test` (pytest), `make check-numbers`, `make check` (both), `make report` (TeX Live with latexmk, pandoc).
- MEEP runs need the conda-forge environment of `environment-meep.yml`: `make m3g MEEPPY=/path/to/env/bin/python`,
  or `PYTHONPATH=. <env>/bin/python scripts/<script>.py`.

## Verification rules

- Fix every threshold before running the check it applies to, and commit it before the run. Never loosen a
  threshold after seeing a result.
- Break each new check once on purpose and confirm that it fails. Record that.
- If a check or control fails on the existing pipeline, report it as a finding. Do not change a number in the report
  or docs silently.
- Time a coarse MEEP run and extrapolate before each production run. In 2D, time scales as resolution^3 (pixels x
  time steps); in 3D, as resolution^4. Record the prediction and the actual time.

## Skills in simulation work

The skills in `.claude/skills/` (vendored from BootLoops, see `NOTICE`) are written for exact computation. Their
terms map onto simulation work as follows.

- **"Digits"** means stability under doubled resolution or a halved step:
  - FDTD or FEM resolution, BPM grid, or BPM dz or time step;
  - stated as the two values and their difference, against a tolerance written down before the run.
- **"Reserved points"** means held-out cases: parameter values, geometries, ports or wavelengths that were not used
  to calibrate or fit the model being checked.
- **"Independent route"** means a second method, such as BPM against MEEP, Kirchhoff against FDTD, or an
  effective-index trace against a 3D vector trace.
  - Always name the layers the two routes share: material data (`picsim/materials.py`), geometry builders,
    mode solver (`picsim/modes.py`, femwell), and launch or projection fields.
  - A shared layer cannot be certified by that comparison.
